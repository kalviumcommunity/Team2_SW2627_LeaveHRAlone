# Structured JSON Output for RAG Assistant

## 1. Overview

The RAG (Retrieval-Augmented Generation) assistant must return both an answer and its source in a predictable JSON format. Free-form text is difficult to parse reliably and can cause errors when the application processes model responses.

This task implements structured JSON generation, parsing, error handling, and required-field validation to ensure that only valid responses are used by the application.

## 2. Objectives

- Instruct the language model to return a predefined JSON structure.
- Parse model responses into Python dictionaries.
- Detect malformed JSON without crashing the application.
- Validate required fields before using the response.
- Recover from invalid responses when possible.
- Save sample parsed results, including a malformed response followed by a successful recovery.

## 3. Required JSON Structure

The assistant must return a JSON object containing the following fields:

```json
{
  "answer": "The answer generated by the RAG assistant.",
  "source": "The document or reference used to generate the answer."
}
```

### Field definitions

| Field | Data type | Required | Description |
|---|---|---|---|
| `answer` | String | Yes | The response generated by the model |
| `source` | String | Yes | The source document or reference supporting the answer |

Both fields must be present and contain non-empty strings.

## 4. Implementation

Create the following Python script:

`scripts/structured_output.py`

### Step 1: Define the prompt

The model prompt must explicitly request valid JSON and prohibit additional prose outside the JSON object.

Example prompt:

```python
SYSTEM_PROMPT = """
You are a RAG assistant.
Return only a valid JSON object with exactly these fields:
{
    "answer": "string",
    "source": "string"
}
Both fields are required and must contain non-empty strings.
Do not include Markdown code fences or text outside the JSON.
"""
```

When the selected model API supports JSON mode or schema-constrained output, enable it to improve format reliability.

### Step 2: Parse and validate the response

Use Python's built-in `json` module to parse the response. Handle parsing failures explicitly and validate the required fields before returning the result.

```python
import json


def parse_response(raw_response):
    """Parse and validate a structured RAG response."""
    try:
        data = json.loads(raw_response)
    except (json.JSONDecodeError, TypeError) as exc:
        return {
            "success": False,
            "error": f"Invalid JSON response: {exc}",
            "data": None,
        }

    if not isinstance(data, dict):
        return {
            "success": False,
            "error": "Response must be a JSON object.",
            "data": None,
        }

    required_fields = ("answer", "source")

    for field in required_fields:
        if field not in data:
            return {
                "success": False,
                "error": f"Missing required field: {field}",
                "data": None,
            }

        if not isinstance(data[field], str) or not data[field].strip():
            return {
                "success": False,
                "error": (
                    f"Field '{field}' must be a non-empty string."
                ),
                "data": None,
            }

    return {
        "success": True,
        "error": None,
        "data": data,
    }
```

### Step 3: Handle malformed responses and recover

If parsing fails, report the problem clearly and retry generation or request a corrected JSON response from the model.

A retry should be bounded to avoid infinite loops. Validate the recovered response again before using it.

Example recovery flow:

1. Receive the model response.
2. Attempt JSON parsing.
3. If parsing fails, record the error.
4. Request a corrected response or retry generation.
5. Parse and validate the new response.
6. Use the result only if validation succeeds.
7. If recovery fails, return a clear error instead of crashing.

A retry must not assume that the corrected response is valid without revalidation.

## 7. Testing and Validation

Test the implementation with the following cases:

- Valid JSON containing both required fields.
- Malformed JSON syntax.
- A JSON array or string instead of an object.
- Missing `answer` or `source` fields.
- Empty strings or fields with incorrect data types.
- A malformed initial response followed by a valid recovered response.
- A recovery attempt that also fails.

The application must never use an invalid response as a successful result.

## 8. Acceptance Criteria

- [ ] The prompt defines the expected JSON structure.
- [ ] JSON mode or schema-constrained output is used when supported by the model API.
- [ ] Valid JSON is parsed into a Python dictionary.
- [ ] Malformed JSON is handled without an unhandled exception.
- [ ] Required fields are checked before the result is used.
- [ ] Missing, empty, and incorrectly typed fields are rejected.
- [ ] Recovery is bounded and recovered responses are revalidated.
- [ ] Sample results include successful parsing and malformed-then-recovered output.
- [ ] The implementation and sample results are committed to Git.
